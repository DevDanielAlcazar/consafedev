# ConSafeDev — Experience Contract V2

## Strategic idea
**Engineered Clarity**

ConSafeDev transforms fragmentation → understanding → structure → software → operation → clarity.

## Core visual thesis
The main experience is not a diagram of systems. It is the transformation of **real operational fragments into a working software product**.

The user witnesses information becoming context, context becoming structure, structure becoming product and product becoming a living system.

## Desired reaction
> “Si así entienden y convierten una operación en producto, quiero hablar con ellos.”

The site must feel premium, spatial, cinematic, intentional, technically credible, modern without trend-chasing and expressive without generic AI-agency aesthetics.

## ConSafeDev Effect
Build 01 V2 is accepted only if:
1. Hero clearly communicates custom software solving real business problems.
2. Hero is visually strong even as a static frame.
3. First scroll creates curiosity.
4. User sees operational reality before software.
5. Software emerges from fragments already present.
6. Transformation changes meaning, not only position.
7. Fragmentation→clarity is understandable without explicit phase UI.
8. Result cannot be mistaken for DevOps tooling, SaaS template UI or a generic AI agency.
9. After Living System the user should infer product-design and engineering maturity.

## Hero approved copy
**Lo complejo puede funcionar simple.**

**Diseñamos software a medida que conecta procesos, automatiza operaciones y convierte problemas reales de negocio en sistemas que funcionan.**

CTA: **Hablemos de lo que necesitas resolver**

Exploration: **Explora cómo lo hacemos**

## Living System approved narrative
1. **Los problemas rara vez empiezan en el software.**
2. **Primero entendemos qué está ocurriendo.**
3. **Diseñamos alrededor del problema. No de una plantilla.**
4. **Después lo convertimos en software que tu equipo puede usar.**
5. **Un sistema que trabaja como trabaja tu negocio. No al revés.**

Optional supports:
- **Empiezan entre procesos, herramientas y decisiones que dejaron de trabajar juntas.**
- **Porque construir bien empieza mucho antes de escribir código.**

## Required visual source
For Hero/Living System, `SCENE_DIRECTION_V2.md` is mandatory and takes precedence over generic component conventions.

## Forbidden visual language
No topology maps, DevOps/service diagrams, monitoring dashboards, numbered phases, phase badges, progress steppers, fake telemetry/KPIs, generic Bento grids, huge glass capsules, cyberpunk/neon purple, aurora-as-main-composition, glowing blobs, random particles, AI brains/robots, globe/cube motifs, fake terminals, stock-team hero photography, tech-logo marquees or completed dashboard as opening Hero visual.

## Page continuity
Future `/agenda` and `/privacidad` are chapters of the same product. Changing route must never feel like changing product.
