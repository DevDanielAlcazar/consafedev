# ConSafeDev — Scene Direction V2
## Hero + Living System

This is the primary visual truth source for Build 01 V2.

# 1. Core idea
We are not showing software. We are showing **the birth of software from operational complexity**.

The user begins inside fragmented business reality: conversations, documents, dates, tasks, customers, approvals, records, alerts, orders, support requests and information.

As the user scrolls: relationships are discovered, noise disappears, fragments gain context, flows emerge, structure appears, structure becomes usable product, and the product becomes a living system.

Emotional sequence: **intrigue → recognition → discovery → coherence → transformation → confidence**.

# 2. Visual character
Spatial, cinematic, editorial, sophisticated, quiet but alive, intentionally composed and technically credible without looking like DevOps tooling.

Never topology, architecture diagram, monitoring dashboard, SaaS template, generic AI agency, Figma card collection or cyberpunk interface.

# 3. Spatial model
Think in depth layers, not rows of cards.

- Foreground: rare high-attention fragments.
- Midground: primary operational fragments and the main transformation.
- Background: faint context that creates depth without competing for attention.

Use asymmetry and negative space. Avoid a uniformly distributed grid.

# 4. Fragment language
Fragments are recognizable pieces of business reality, not generic nodes.

Possible text fragments: `cliente`, `agenda`, `pedido`, `inventario`, `documento`, `soporte`, `seguimiento`, `aprobación`, `registro`, `revisión`, `entrega`, `incidencia`.

Possible visual fragments: date, short ID, one table row, status, timestamp, message bubble, unread state, filename, validation mark, pending/assigned/approved/completed, small input/tab/list/notification.

At the beginning these must feel like pieces of an operation, not completed software modules.

# 5. HERO — first impression
Approved copy:

**Lo complejo puede funcionar simple.**

**Diseñamos software a medida que conecta procesos, automatiza operaciones y convierte problemas reales de negocio en sistemas que funcionan.**

CTA: **Hablemos de lo que necesitas resolver**

Exploration cue: **Explora cómo lo hacemos**

Do not place a rectangular visual panel to the right. Operational fragments occupy the environment around and beyond the copy. Some may be partially outside the viewport. Some are closer, some farther. Initial motion is restrained: subtle drift, tiny depth response and a few incomplete traces.

The user should think: **“There is something going on here.”** Not: **“This is a dashboard.”**

Teal is very limited at the start. Teal progressively means active/connected/meaningful.

# 6. SCROLL BEAT 01 — Fragmentation
Narrative: **Los problemas rara vez empiezan en el software.**

Optional support: **Empiezan entre procesos, herramientas y decisiones que dejaron de trabajar juntas.**

Fragments become more legible. The user recognizes messages, documents, approvals, dates, tasks, records and statuses. Relationships remain incomplete. Tension is subtle: things exist, but they do not form a coherent system.

# 7. SCROLL BEAT 02 — Understanding
Narrative: **Primero entendemos qué está ocurriendo.**

Optional support: **Porque construir bien empieza mucho antes de escribir código.**

This is the first major wow moment. Do not add more fragments. Instead, irrelevant fragments recede, meaningful fragments sharpen, groups begin to form, relationships are discovered, duplicated information consolidates, and loose requests gain context.

No scanners, holograms, terminals or AI iconography.

# 8. SCROLL BEAT 03 — Architecture
Narrative: **Diseñamos alrededor del problema. No de una plantilla.**

Business/product structure emerges, not infrastructure topology.

Possible transformations: message + customer + date begin to form a scheduling flow; document + validation + review begin to form a document-processing flow; support request + ownership + status begin to form a service flow; order + inventory + approval begin to form an operational flow.

Lines become cleaner, groups align, layers resolve and teal progressively activates meaningful relationships. Still no completed dashboard.

# 9. SCROLL BEAT 04 — Construction / Product Emergence
Narrative: **Después lo convertimos en software que tu equipo puede usar.**

This is the main transformation moment.

**Software must emerge from fragments already on screen.** Do not fade out the scene and fade in an unrelated dashboard.

Examples: free-floating document → validation queue; chat fragment → ticket/request row; date + person → scheduling control; isolated status → workflow state; scattered data rows → usable table; approval fragment → real interaction control; scattered alerts → restrained notification area.

The user must mentally trace: **“that thing became this thing.”**

# 10. SCROLL BEAT 05 — Living Product
Narrative: **Un sistema que trabaja como trabaja tu negocio. No al revés.**

The product is now coherent but not a generic dashboard screenshot. Show a restrained input → process → result cycle. No casino motion, glowing counters or fake KPIs.

Emotional goal: **“I just watched complexity become a working product.”**

# 11. Engineering → Clarity transition
Resolution, not route change. Dark depth flattens, fragments finish their role, one active teal path may continue forward, and the canvas progressively becomes paper/light. No hard white cut or page-loader wipe.

# 12. Text placement
Story copy must not live inside floating cards. No `FASE`, `01/05`, phase badges or progress UI. Typography is part of the editorial composition.

# 13. Progress indication
No visible stepper. If any progress cue exists, it must be nearly subliminal and never look like product UI.

# 14. Pointer behavior
Desktop only: tiny depth response, focus, subtle clarity. No custom global cursor or hover-required meaning.

# 15. Mobile direction
Mobile is not compressed desktop. Use fewer, larger fragments and bigger semantic transformations. Keep the same sequence: fragmentation → understanding → architecture → product → living product. No tiny topology lines or hover logic.

# 16. Static Frame Test
Pause at Hero, Fragmentation, Understanding, Product Emergence and Living Product. Every frame must look intentionally art-directed.

Fail if any paused frame resembles generic SaaS, DevOps/ITSM, network topology, admin dashboard template or random card cluster.

# 17. Transformation Test
Valid transformation changes meaning, not only position.

Invalid: move box; connect nodes; change badge gray→teal.

Valid: message→ticket/request; document→validation workflow; person+date→scheduling context; scattered data→usable operational view; fragmented status→actionable process.

# 18. Negative reference — rejected Build 01
Explicitly rejected: topology maps, orthogonal conduits, BUS, PORT labels, observability aesthetics, numbered stepper, phase badges, fake telemetry, invented metrics, uniformly distributed boxes, story copy inside cards, dark technical UI for its own sake.

Do not recreate or improve that direction.

# 19. Definition of success
Hero looks premium even paused; custom software is clear; scene is spatial not grid-based; operational fragments feel real; scroll creates curiosity; transformations change meaning; software visibly emerges from operational reality; teal gains semantic meaning; mobile preserves the same emotional story; result cannot be mistaken for a generic AI/software agency template.
